# Most Used sort add-on

`addon-most-used` is an independent Android APK that provides `modular.apps.sort/v1` to Modular Core protocol 4. Its stable provider ID is `modular.addon.sort.mostused`. The release package is `io.github.alexanderwilhelmsenberg.modular.addon.sort.mostused`; the debug package adds `.debug`. In Modular, open the module’s **Settings**, choose **Recent days** (1–30, default 7), then **Use on Home**. Core manages its instance and Home binding automatically.

The add-on orders the supplied app entries by Android's `UsageStats.totalTimeInForeground` for each package, descending. It queries `UsageStatsManager.queryAndAggregateUsageStats` for a rolling `days × 24 hours` interval ending at sort time. Android aggregates its stored interval records that overlap the requested window, so the result is an approximate foreground-time total, not an exact cutoff or a launch count. Multiple activities in the same package receive the same package total. Only records for the add-on's current Android profile are available; supplied entries from other profiles receive zero measured time. Equal or zero totals use locale-aware alphabetical order, then exact label and key fields for stable ties. All supplied entries are retained.

Android requires the user to grant Usage Access separately. In the module’s **Settings**, open **Permissions and settings** to see the current status and open Android’s Usage Access screen. The add-on’s launcher entry opens the same screen; **Configure in Modular** returns to its Core settings. When access is off or revoked, the provider returns a failure so Core keeps its alphabetical fallback and records a sort diagnostic. When access is on but Android has no records, the provider returns a successful alphabetical order. Android's aggregate API returns package records for the current profile; the add-on immediately filters them to package names supplied by Core. It does not log, save, or upload usage data.

Build from the repository root with `:addon-most-used:assembleDebug` or `:addon-most-used:assembleRelease`. The module uses the same optional `MODULAR_KEYSTORE_PATH` and `MODULAR_KEYSTORE_PASSWORD` environment variables and `modular-debug`/`modular-release` aliases as the reference add-on. Persistent signing is required for the SDK's official same-signer Core policy; disposable local debug signing will not pair with a separately signed Core APK.
